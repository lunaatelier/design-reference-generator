Background

0. 추진 배경

요구사항 누락, 산출물 편차, 근거 추적 한계를 줄이기 위한 자동화 필요성을 정리합니다.

요약

목표는 AI로 기획서를 빠르게 생성하는 것이 아니라 RFP 요구사항의 누락·오염을 줄이고, 기획자별 산출물 편차를 낮추는 것입니다.

1

요구사항 무결성 확보

RFP·회의록에서 요구사항을 분해하고 REQ-ID → IA → SCR-ID → ui_spec → QA까지 추적합니다.

2

기획자 편차 감소

Slot-Filling과 상태/예외 매트릭스로 기획 담당자도 일정 기준 이상의 UI 기획서를 작성하도록 지원합니다.

3

검증 가능한 운영 체계

UI 설계 정합성, 휴리스틱 품질, 도메인 룰팩, 보안 Gate, KPI를 연결합니다.

왜 기획·설계 자동화 2.0이 필요한가

v1.0은 프롬프트와 UI 설계서 생성까지 가능하지만, AI 요약·압축으로 인한 누락, 오염, 임의 스킵, 품질 일관성 문제가 남아 있습니다.

요구사항 누락·오염

AI가 RFP 원문을 요약하면서 핵심 요구사항을 누락하거나, 원문에 없는 기능을 추가할 수 있습니다.

숙련도 편차

도메인 경험, 상태/예외 정의, UX 방법론 활용 수준에 따라 산출물 품질이 달라집니다.

검증 리소스 한계

Human-in-the-Loop의 중요성은 높지만 모든 요구사항과 화면을 사람이 전수 검증하기 어렵습니다.

핵심 구조: Track 1은 요구사항의 누락과 오염을 막는 기반 엔진이고, Track 2는 기획자가 실제로 사용하는 UI 설계 생산성·품질 도구이며, Track 3은 도메인 특화 지식을 룰팩과 Workflow로 확장하는 고도화 영역입니다.

실행 방법: 3대 Track 기준 운영 방식

실행 방식은 Track별 독립 수행과 통합 검증으로 구성합니다. 협업 루프를 과도하게 늘리지 않고, 산출물 기준으로 연결성과 품질을 검증합니다.

Track 1
요구사항 추적
실행 방법: RFP/회의록에서 요구사항을 분해하고 REQ-ID를 부여합니다. 각 요구사항은 SOURCE-REF로 원문 근거를 연결합니다.

Track 2
